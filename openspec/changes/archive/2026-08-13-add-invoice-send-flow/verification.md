## Widerlegt

- `design.md` Z.79-80: "`CustomerResource.php:38` ... `invoice.customer.user.email` ist bereits im JSON-Payload enthalten" — die Zeilenangabe ist falsch. `CustomerResource.php:38` enthält tatsächlich `'paymentMethod' => $this->payment_method` (siehe `backend/app/Http/Resources/CustomerResource.php:38`), nicht das E-Mail-Feld. Das E-Mail-Feld kommt aus der verschachtelten Resource: `CustomerResource.php:47` (`'user' => new UserResource($this->whenLoaded('user'))`) und `UserResource.php:29` (`'email' => $this->email`). Die **funktionale** Kernaussage (E-Mail ist im Payload vorhanden, wenn `customer.user` geladen ist) bleibt richtig, nur der Zeilen-Beleg ist falsch zitiert.
- `design.md` Z.35-37: "`envelope()` (Zeile 34-49) setzt Absender aus `Setting::get('company_email'/'company_name')`" — ungenau. Der tatsächliche Code ruft **nicht** die Model-Methode `Setting::get()` auf (die existiert zwar in `backend/app/Models/Setting.php:62`), sondern führt eine eigene `Cache::remember('email_settings', ..., fn () => Setting::whereIn('key', [...])->pluck('value', 'key')->toArray())`-Query aus (`InvoiceCreated.php:36-40`) und greift dann per Array-Zugriff (`$settings['company_email'] ?? env(...)`) zu. Die beschriebene Wirkung (Firmen-E-Mail/-Name aus `Setting` mit `env()`-Fallback) ist korrekt, der genannte Mechanismus (`Setting::get()`) nicht.
- `design.md` Z.64-70: Testdatei-Umfang "(65 Zeilen)" — tatsächlich hat `backend/tests/Feature/InvoiceCreatedMailBankDetailsTest.php` **64 Zeilen** (`wc -l`). Geringfügige Abweichung, ohne inhaltliche Relevanz.
